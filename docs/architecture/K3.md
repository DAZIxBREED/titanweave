# WeaveCore K3 Architecture Note

## Purpose

K3 proves that WeaveCore can regain control at periodic hardware deadlines,
save a complete interrupted kernel context, choose another runnable task, and
return through `iretq` on the selected task's stack.

## Scheduling path

```text
Local APIC timer
      ↓ vector 0x40
Assembly register save
      ↓
InterruptFrame on current task stack
      ↓
weave_schedule_dispatch(frame)
      ↓
Store current frame and update run queue
      ↓
Choose next Ready task
      ↓
Return next task's saved frame address
      ↓
Assembly register restore + iretq
```

Blocking and task exit use software interrupt vector `0x41`, which enters the
same frame-selection path without acknowledging a hardware interrupt.

## Per-CPU state

K3 allocates scheduler-state and run-queue structures for every logical CPU.
Only the BSP queue is activated. AP activation is deferred until cross-CPU
wakeups, scheduler locking, IPIs, and independent timer policy are defined.

## TSS and IST

Every logical CPU receives:

- Its own GDT.
- Its own 64-bit TSS.
- IST1 for double fault.
- IST2 for NMI.
- IST3 for machine check.

These paths use emergency serial output and halt rather than attempting normal
scheduler recovery.

## Timer calibration

K3 programs PIT channel 2 as a polled 10 ms one-shot, starts the Local APIC
timer at `u32::MAX` with divide-by-16, and measures the elapsed APIC count. The
measured count becomes the periodic 100 Hz scheduler quantum.

The PIT is a bootstrap calibration dependency, not the intended permanent
Titanweave time source.

## Kernel event

The first kernel object is an auto-reset event with:

- Stable object ID.
- Object kind.
- Atomic reference count.
- Wait queue.
- Latched signaled state.

A waiter disables local interrupts, enqueues itself, marks its task blocked,
and invokes vector `0x41`. A signal wakes one waiter or remains latched when no
waiter exists.

## Safety boundary

K3 deliberately avoids preempting while a spin lock is held. The lock guard
saves RFLAGS, disables local interrupts, and restores the previous interrupt
state when released. This is a temporary kernel-wide rule until a formal
preemption counter and lock hierarchy are introduced.
