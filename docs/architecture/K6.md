# K6 Architecture: Bootstrap Storage and Disk-Backed Userspace

## Purpose

K6 establishes the first persistent-system boundary without prematurely moving
a full filesystem or storage driver into trusted kernel code.

## Two-view system image

`TITANFS.IMG` is presented in two forms:

1. The UEFI loader reserves a complete memory copy and describes it as a boot
   volume in `BootInfo v7`.
2. QEMU attaches the same bytes as a transitional VirtIO block device.

WeaveCore uses the memory copy for its first read-only FAT32 mount and separately
performs a DMA sector read through VirtIO. This makes failures diagnosable and
keeps a recovery path while the transport is new.

## Trusted bootstrap parser

The K6 FAT32 implementation is intentionally bounded:

- 512-byte sectors.
- Power-of-two sectors per cluster.
- FAT32 cluster chains.
- Read-only operation.
- 8.3 names only.
- Fixed 128 KiB file scratch buffer.
- No long-file-name records.
- No writes, allocation, deletion, or repair.

The eventual storage service may support broader FAT behavior. The kernel only
needs enough to load early native services safely.

## VirtIO queue proof

The K6 QEMU profile exposes a transitional device. WeaveCore:

- Locates the PCI function.
- Enables I/O-space and bus-master access.
- Resets and acknowledges the device.
- Negotiates no optional features.
- Allocates a physically contiguous legacy split virtqueue.
- Submits a three-descriptor block read request.
- Polls the used ring.
- Validates the returned status byte and `0xAA55` sector signature.

This is a proof path, not the final DeviceKit block driver.

## Service loading

The service table contains Windows-style paths. The kernel opens each through
VFS and passes the bytes to the existing ELF loader. Individual user programs
are no longer loader modules.

## Namespace and shared memory

K6 adds fixed-capacity prototypes for named objects. These prove the naming and
lookup semantics that later user-space service discovery and capability transfer
will expose through normal syscalls.
