# K13 — Native GPU Acceleration Foundation

K13 forks from the frozen, QEMU-qualified K12 tree. K12's display/compositor
contract remains the compatibility baseline; K13 adds the hardware-acceleration
layer behind ForgeGraphics without moving desktop policy back into WeaveCore.

## K13 end-state goals

1. Discover and classify PCI graphics adapters without granting DMA merely for
   being present.
2. Bind accelerated graphics drivers through ForgeBus with explicit IOMMU/DMA
   ownership and crash revocation.
3. Provide backend-neutral GPU buffer objects across System, GTT/shared, and
   dedicated VRAM domains with budgets, ownership, pinning, migration, and
   reclamation.
4. Provide bounded command queues and timeline fences suitable for graphics,
   compute, copy, and presentation engines.
5. Provide atomic display/modeset contracts for connectors, scanout buffers,
   refresh, and later VRR/HDR capability negotiation.
6. Preserve the K12 firmware framebuffer as recovery/fallback while accelerated
   scanout is brought online.
7. Keep multi-GPU a first-class policy: same-adapter, peer-to-peer, shared
   system-memory, and CPU-staged transfers are explicit routes rather than
   hidden special cases.
8. Qualify the generic path first with VirtIO-GPU in QEMU, then attach native
   AMD, Intel, and NVIDIA backends to the same ForgeGraphics acceleration ABI.

## K13 phased implementation

### K13.A — acceleration foundation (this source tree)

Implemented now:

- boot/workspace milestone version 0.13 / protocol v13;
- side-effect-free PCI GPU topology discovery;
- vendor classification for AMD, Intel, NVIDIA, and VirtIO-GPU;
- buffer-object lifecycle and System/GTT/VRAM budget model;
- bounded command-packet queue contract;
- monotonic timeline-fence contract;
- atomic modeset request validation;
- multi-GPU route selection policy;
- probe-only VirtIO-GPU discovery under default-deny DMA policy;
- `SYS_GPU_QUERY` userspace visibility;
- DISPLAYD awareness of the K13 GPU topology;
- dedicated K13 source and QEMU qualification tooling.

Not claimed by K13.A:

- no GPU BAR is mapped by the new VirtIO probe;
- no GPU bus mastering is enabled by the new probe;
- no VirtIO control/cursor virtqueues are initialized yet;
- no accelerated command is submitted yet;
- no native AMD/Intel/NVIDIA register programming is performed yet;
- `transport_ready=false` is intentional until a backend owns an IOMMU domain,
  command transport, interrupt/fence path, and reset/recovery path.

### K13.B — VirtIO-GPU transport (frozen / qualified)

Implemented in this slice:

- ForgeBus ownership before MMIO/DMA activation;
- modern PCI capability walk for common, notify, ISR, and device regions;
- VirtIO `VERSION_1` feature negotiation;
- bounded split control/cursor virtqueues;
- ForgeBus-owned DMA pages for queues, command workspace, and scanout backing;
- `GET_DISPLAY_INFO`;
- 2D resource creation and backing attachment;
- scanout binding;
- transfer-to-host and resource flush;
- polled bootstrap completion;
- timeout/reset + PCI bus-master disable;
- `transport_ready=true` exposure to DISPLAYD;
- K12 GOP/stdvga fallback retained throughout qualification.

Current hardening boundary: Titanweave's K11 VT-d/AMD-Vi layer does not yet
program complete hardware translation page tables. K13.B therefore does not
negotiate VirtIO `ACCESS_PLATFORM`; QEMU uses bounded ForgeBus DMA ownership
with `iommu_platform=off`. Hardware-enforced translated GPU DMA is required
before a bare-metal production-completeness claim.

### K13.C — buffered compositor presentation (frozen / qualified)

Implemented in this slice:

- persistence of the already-qualified K13.B live transport state;
- three VirtIO-GPU scanout-capable presentation resources;
- checked dirty-rectangle clipping and transfer offsets;
- rotating buffered presentation with partial transfer-to-host updates;
- `VIRTIO_GPU_FLAG_FENCE` presentation flushes with device-echoed fence IDs;
- backend-neutral pacing and presentation-watchdog policy;
- capability-mediated `SYS_GPU_PRESENT` requiring a DISPLAYD-only graphics-present capability handle;
- DISPLAYD-triggered live present qualification;
- K12 GOP recovery/fallback kept armed throughout.

Current truth boundary: K13.C is GPU-presented but still CPU-composited. Native
GPU blit/raster/shader engines, asynchronous MSI-driven fence completion, vblank
pacing, direct userspace scanout-buffer ownership, and complete translated-IOMMU
GPU DMA remain later K13 work.

### K13.D — resilience and multi-GPU robustness (current source tree)

Implemented in this slice:

- backend-neutral GPU health/recovery state machine;
- bounded hot-plug and multi-scanout generation policy;
- primary/standby adapter promotion policy;
- two-VirtIO-GPU QEMU topology with only one active DMA transport;
- 64-frame live presentation soak with monotonic device-echoed fences;
- controlled accelerated-path suspension while K12 GOP fallback remains armed;
- rearm of the already-owned VirtIO-GPU transport;
- capability-mediated DISPLAYD recovery syscall;
- dedicated K13.D serial qualification.

Truth boundary: K13.D validates generic/QEMU resilience behavior. It does not
claim physical PCI FLR/slot power-cycle recovery, native-vendor engine reset,
peer-to-peer physical-GPU DMA, or complete atomic multi-monitor presentation.

### Later native-backend work

AMD, Intel, and NVIDIA backends will attach behind the same ForgeGraphics and
resilience contracts. Native drivers must not require compositor ABI changes.
Hardware-translated GPU IOMMU mappings, MSI/MSI-X completion, vblank/VRR, native
reset paths, and physical multi-GPU peer-copy require separate bare-metal
qualification.

## Safety boundary

GPU discovery is not authorization. A K13 backend may touch device MMIO or enable
bus mastering only after ForgeBus ownership, capability checks, and a DMA/IOMMU
domain are established. A failed/hung backend must be fenceable without taking
storage, input, recovery, or another GPU with it.

## K13.A qualification markers

A successful foundation run emits:

- `[BOOT] WeaveCore K13 entered from WEAVECORE.ELF`
- `[GFX ] K13 GOP scanout online:`
- `[GPU ] K13 topology:`
- `[VRAM] domain lifecycle self-test:`
- `[CMDQ] bounded submission self-test:`
- `[FENC] timeline self-test:`
- `[MODE] atomic modeset contract:`
- `[MGPU] transfer policy self-test:`
- `[VGPU] VirtIO-GPU candidate at ... probe_only=true`
- `[GACC] ForgeGraphics acceleration ABI v1 foundation passed transport_ready=false`
- `[GPUF] K13 acceleration foundation ready:`
- `[USER] [displayd] K13 display/compositor service online`
- `[KERN] K13 alive:`
- `[QUAL] K13 foundation runtime reached intentional post-userspace halt`

Passing K13.A means the acceleration architecture and discovery foundation are
runtime-qualified. It does **not** mean K13 as a whole is frozen or that hardware
acceleration is complete.

## K13.C qualification markers

A successful buffered-presentation run adds:

- `[PACE] compositor pacing contract:`
- `[FBCK] presentation watchdog policy:`
- `[PRES] triple-buffered compositor scanout online:`
- `[DMG ] dirty-region GPU uploads verified:`
- `[PFEN] fence-verified presentation complete:`
- `[GCOMP] K13.C compositor presentation ready:`
- `[GPRE] K13.C buffered presentation ready:`
- `[UPRS] DISPLAYD present:`
- `[USER] [displayd] K13.C capability-mediated buffered present verified`
- `[KERN] K13.C alive:`
- `[QUAL] K13.C presentation runtime reached intentional post-userspace halt`

Passing K13.C qualifies the buffered VirtIO-GPU presentation path in QEMU. It
does not complete K13 or qualify native vendor GPU acceleration.

- `[MOUT] multi-scanout policy self-test:`
- `[MGP2] multi-GPU presentation policy:`
- `[SOAK] presentation stress:`
- `[DLOS] controlled device-loss fence:`
- `[REBD] transport rearm verified:`
- `[GRDY] K13.D resilience/multi-GPU ready:`
- `[URCV] DISPLAYD recovery:`
- `[KERN] K13.D alive:`
- `[QUAL] K13.D robustness runtime reached intentional post-userspace halt`

Passing K13.D qualifies the generic VirtIO-GPU resilience/multi-adapter runtime
path in QEMU. It does not by itself qualify native physical GPU drivers.
