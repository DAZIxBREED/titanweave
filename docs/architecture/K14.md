# K14 — Native GPU and Hardware-DMA Bring-up

K14 forks from the frozen, QEMU-qualified K13.D baseline. K13 remains the
working generic GPU contract: ForgeGraphics, presentation, resilience,
multi-GPU policy, VirtIO-GPU and GOP fallback are retained rather than replaced.

## Goal

Move Titanweave from a qualified virtual GPU backend to safe bare-metal GPU
support without weakening the capability, DMA, recovery or fallback rules built
in K11-K13.

## K14.A — native prerequisite foundation (this tree)

- Read-only AMD/Intel/NVIDIA PCI discovery and BAR inventory.
- Stable `NativeGpuBackend` lifecycle contract.
- Explicit states from discovery through acceleration-ready.
- Native DMA admission gate: ForgeBus ownership + hardware-translated IOMMU are
  mandatory before bus mastering is authorized.
- Truthful classification of the current K11 AMD-Vi/VT-d implementation as
  `PolicyOnly`, not hardware-translated.
- Native-GPU status syscall for DISPLAYD.
- Qualified K13 VirtIO-GPU and K12 GOP paths remain active fallbacks.

K14.A does **not** write vendor MMIO, size BARs by destructive probing, enable
bus mastering, load GPU firmware, negotiate GPU rings, or claim native hardware
acceleration.

## K14.B — hardware-translated DMA (current tree)

- Live Intel VT-d root/context/second-level page-table programming.
- ForgeBus-owned per-device IOVA mappings with explicit read/write permissions.
- Context-cache and IOTLB invalidation with bounded completion waits.
- Real DMA allow/deny proof using the QEMU EDU endpoint.
- Fail-closed ordering: ownership and mappings precede bus mastering; bus
  mastering is disabled before domain revocation.
- Hardware-translation qualification is separated from native-GPU domain
  binding, so K14.C still must attach a concrete GPU before activation.
- AMD-Vi retains the same backend handoff but requires an IVRS bare-metal
  qualification before Titanweave may claim live AMD translated DMA.
- Persistent VirtIO `ACCESS_PLATFORM` migration remains an integration follow-up
  rather than being falsely claimed by this short qualification window.

## K14.C — first native vendor backend

### K14.C1 — ownership foundation (frozen/qualified)

- AMD-first candidate selection and ForgeBus claim path.
- Non-destructive BAR inventory and fail-closed bus-master state.
- Backend-neutral VRAM/GTT ownership model and DISPLAYD binding query.
- Translation-engine qualification is kept distinct from a persistent per-GPU domain.
- QEMU qualifies the generic contracts honestly with no fake Radeon device.

### K14.C2 — persistent domain and Radeon bring-up (current tree)

- Retains one real VT-d requester/domain across multiple DMA epochs in QEMU, then explicitly revokes it.
- Carries AMD-first ASIC identity from C1 ownership into the bring-up layer.
- Defines firmware roles for VBIOS, PSP, SMU, GC, SDMA and scheduler/MES-family components.
- Defines command-ring bootstrap geometry and lifecycle ordering.
- Keeps actual Radeon MMIO writes, firmware upload, bus mastering and command submission fenced until the physical GPU RID has its own translated domain.

### K14.C3 — Radeon bare-metal staging (current tree)

- Establishes explicit AMD IP bring-up ordering (PSP, SMU, GMC, IH, SDMA, GC, DCN).
- Adds firmware-role and MMIO/doorbell safety contracts without writing vendor registers.
- Requires ForgeBus ownership plus a persistent translated domain for the exact Radeon requester before MMIO/firmware/command gates can advance.
- Treats AMD-Vi/IVRS hardware translation as a separate bare-metal qualification requirement; Intel VT-d/QEMU success is not promoted to an AMD requester.
- Retains K13 VirtIO-GPU and K12 GOP fallback until native scanout is qualified.

AMD remains the intended first bare-metal backend, followed by Intel and NVIDIA behind the same ForgeGraphics contract. Vendor-specific code must not leak into DISPLAYD or the generic ABI.

## Locked K14 closure — C27 through C32

The project owner superseded the earlier provisional K14.D split with the locked C27-C32 roadmap. There is no separate K14.D milestone.

- C27: complete Radeon driver core — qualified/frozen.
- C28: memory + firmware + recovery — qualified/frozen.
- C29: rings + queues + fences + DMA — qualified/frozen.
- C30: complete basic display engine — qualified/frozen.
- C31: graphics + compute execution — qualified/frozen.
- C32: production/stability + final K14 — source-integrated; runtime qualification pending in this tree.

C32 owns queue/memory/interrupt/recovery stress, display/compute coexistence, repeated scanout, multi-display framework checks, multi-GPU inventory groundwork, diagnostics, power policy, shader-precache freeze and the userspace GPU ABI/capability freeze. QEMU qualification remains explicit reference/control-plane evidence; physical Radeon stress is tracked independently. After C32 qualifies, K14 is complete/frozen and K15 ForgeAudio begins.

## Non-goals

K14 does not implement DirectX translation, shader compiler stacks, ROCm/CUDA,
full 3D APIs, or application compatibility. Those consume the native GPU layer
later; they are not prerequisites for safely owning a physical GPU.
