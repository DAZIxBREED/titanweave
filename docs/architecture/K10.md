# K10 — Aegis Trust and Signed Execution

K10 turns K9 package transactions into an enforceable trust boundary for applications, drivers, services, updates, and firmware.

## Implemented

- Freestanding streaming SHA-256 with constant-time digest comparison.
- Bounded trust-key store with signer tiers, disablement, and content revocation.
- Signed manifest contract binding content identity, signer, version, subject kind, capabilities, and minimum system version.
- Capability ceilings for applications, drivers, services, updates, and firmware.
- Mandatory System/Platform signatures for privileged drivers, updates, and firmware.
- Explicit approval records for user-signed capability requests.
- A/B update activation, health confirmation, failed-boot rollback, and anti-rollback floors.
- Persistent `TRUSTD.ELF` userspace Trust Service.
- Boot-time cryptographic and update-policy self-tests.

## Security boundary

The kernel owns immutable policy decisions, revocation, capability ceilings, and update activation state. `TRUSTD.ELF` owns policy distribution and user-facing approvals. Codec parsing remains in the K9 Archive Service.

## Signature backend

`trust::SignatureVerifier` is deliberately a narrow cryptographic-provider interface. The K10 policy engine never treats a digest or checksum as a signature. A production asymmetric verifier must implement this interface and be backed by reviewed cryptographic code or a hardware security provider before production signing keys are enrolled.
