# WeaveCore K4 Architecture Note

## Purpose

K4 proves that WeaveCore can stop treating every instruction as trusted kernel
code. It creates one isolated ring-3 process, enters it through an architectural
privilege transition, accepts bounded system calls, validates capabilities
represented by handles, and returns cleanly when the process exits.

## Address-space model

K4 clones the kernel's supervisor-only bootstrap mappings into a new PML4. It
then reserves PML4 slot 2 for user memory beginning at `0x0000010000000000`.
The process receives:

- One read/execute code page.
- One read/write stack page at the top of a 2 MiB user region.
- No user permission on the kernel's low identity map.
- No user permission on the higher-half kernel mapping.

The current kernel uses physical addresses through the retained supervisor-only
identity map. This is an early bootstrap convenience and not the final virtual
memory design.

## Privilege transition

The GDT includes ring-3 data selector `0x1b` and code selector `0x23`. Before
launch, WeaveCore installs a dedicated syscall stack into the active CPU's TSS
`RSP0`. `weave_enter_user` switches CR3 and constructs an `IRETQ` frame.

Vector `0x80` is a DPL-3 interrupt gate. Hardware switches to `RSP0`, pushes the
user return state, and enters the common syscall assembly stub. The stub saves
all general registers and passes a 176-byte `UserTrapFrame` to Rust.

## Syscall safety

K4 does not accept raw kernel object pointers from user mode. Calls identify
objects through process-local integer handles. Every operation checks:

1. Handle-table bounds.
2. Handle presence.
3. Object type.
4. Required rights.
5. Pointer range and integer overflow.
6. Read or write permission of the mapped user region.
7. Maximum transfer size.

Only then does the kernel copy bytes or operate on the object.

## IPC proof

Handle `2` refers to a bounded loopback channel. The channel stores one message
up to 64 bytes. The embedded process sends `PING`, receives it into its stack,
and writes it through console handle `1`.

This is intentionally not yet a production channel. K6 must add endpoint pairs,
blocking waits, process-to-process transfer, and capability attachment.

## Exit path

`exit` does not return through `IRETQ`. WeaveCore switches from the process CR3
back to the loader-established kernel CR3, discards the syscall frame by
installing a clean kernel stack, and jumps to `weave_user_exit_resume`.

This proves that process teardown can regain a known kernel execution context
without trusting the user stack.
